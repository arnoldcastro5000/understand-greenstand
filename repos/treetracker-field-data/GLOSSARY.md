## Domains

### Raw Capture Ingestion

Owns the raw tree captures that treetracker app devices upload. It creates, queries, verifies and rejects captures, coordinating dual writes to the field-data and legacy databases and emitting domain events for each action.

**Terms:** RawCapture, Capture

**Rules:**

- A capture write spans the main field-data database and the legacy database in one atomic unit; failure rolls back both
- Each capture create or reject raises a matching domain event (capture-created / capture-rejected)
- A capture references its session, wallet registration and device configuration

**Flows:**

- **Create Raw Capture** (`POST /captures`): Accepts a new raw tree capture from a device, persists it to the field-data and legacy databases in a dual transaction, and publishes a capture-created event.
- **Reject Raw Capture** (`PATCH /captures`): Marks an existing raw capture as rejected, rejects the corresponding legacy tree, and publishes a capture-rejected event.
- **Query Raw Captures** (`GET /captures`): Returns raw captures as a paginated list with prev/next links or as a single capture by id.

### Session & Track Tracking

Records field capture sessions, session segments, and device movement tracks. It provides transactional creation and paginated queries for sessions and tracks that captures reference.

**Terms:** Session, SessionSegment, Track

**Rules:**

- Sessions carry an organization id used to bridge captures to organizations
- Session and track creation run inside a database transaction with rollback on failure

**Flows:**

- **Create Session** (`POST /session`): Validates and persists a new field capture session inside a database transaction.
- **Query Sessions** (`GET /session`): Returns sessions joined with wallet and device configuration data as a paginated list or a single session by id.
- **Track Device Movement** (`/track`): Creates device movement track records transactionally and returns them as a paginated list or single track by id.

### Device Configuration

Registers and queries the configuration of treetracker devices in the field. Configurations are created transactionally and joined into captures for provenance.

**Terms:** DeviceConfiguration

**Rules:**

- Device configuration creation is wrapped in a database transaction

**Flows:**

- **Register Device Configuration** (`POST /device_configuration`): Validates and creates a device configuration record inside a database transaction.
- **Query Device Configurations** (`GET /device_configuration`): Returns device configurations as a paginated list with total count and prev/next links or a single configuration by id.

### Wallet Registration

Registers the wallets that captures are attributed to and lets clients query them. Creation is idempotent, returning the existing record on duplicate, and is backfilled from legacy data via ETL.

**Terms:** WalletRegistration

**Rules:**

- Creating a wallet registration is idempotent: a duplicate returns the existing record
- Creation runs inside a transaction that rolls back on error

**Flows:**

- **Create Wallet Registration** (`POST /wallet_registration`): Validates and idempotently creates a wallet registration inside a transaction, returning the existing record on duplicate.
- **Query Wallet Registrations** (`GET /wallet_registration`): Returns wallet registrations as a paginated list with prev/next links or a single registration by id.

### Domain Events & Messaging

Implements the event-sourcing outbox and RabbitMQ messaging that carry capture events out of the service and back in for processing. It publishes, consumes, and replays domain events with at-least-once delivery.

**Terms:** DomainEvent

**Rules:**

- Domain events are persisted to a partitioned outbox table before and after publication
- Incoming events are processed inside a transactional session; failure rolls back and re-queues via republish/nack recovery
- Stored events can be replayed by re-publishing or re-applying handlers for recovery

**Flows:**

- **Publish Capture Event** (`RawCapture create/reject`): Raises a domain event on a model, persists it to the outbox, and publishes it to RabbitMQ for downstream consumers.
- **Consume Capture Event** (`RabbitMQ capture-creation subscription`): Subscribes to the capture-creation queue and processes incoming events inside a transactional session, updating domain event state on success or rollback.
- **Replay Domain Events** (`POST /replay_event`): Loads stored domain events and re-publishes them to the queue or re-applies their handlers for recovery.

### Legacy Database Bridging

Bridges field-data records into the legacy treetracker main database during migration. It maps captures to legacy tree, planter and attribute records and backfills wallet registrations and session ids from legacy data.

**Terms:** LegacyTree, LegacyPlanter, LegacyTreeAttribute, LegacySession

**Rules:**

- Each new capture is dual-written as a legacy tree with its planter lookup and tree attributes
- Rejecting a capture also rejects the corresponding legacy tree via the legacy API

**Flows:**

- **Dual-Write Legacy Tree** (`RawCaptureService.createRawCapture`): Maps a new capture into legacy tree records and persists them with a planter lookup and bulk tree-attribute inserts into the legacy database.
- **Backfill From Legacy ETL** (`database/etl scripts`): One-off ETL that generates legacy session ids and builds wallet registration rows from legacy data during migration.
