## Domains

### Tile Rendering

Handles incoming web-map tile requests for the Tree Tracker map. It parses x/y/z tile coordinates, builds a Mapnik map instance with the correct envelope and style, renders the PostGIS features, and returns a PNG tile.

**Terms:** Tile (x/y/z), Map instance, PNG image, Bounding-box envelope

**Rules:**

- Zoom-level settings must be present at startup or the server refuses to boot
- Each request builds a fresh Mapnik map for its tile envelope

**Flows:**

- **Render Map Tile** (`GET tile route (x/y/z)`): End-to-end handling of a tile request: parse coordinates, build the map, query data, render, and return a PNG.

### Map Query Building

Selects and assembles the correct PostGIS SQL for a tile request. A Map controller inspects request settings (tree id, user, wallet, timeline, zoom target) and instantiates the matching SQL query-builder from a case-based class hierarchy.

**Terms:** SQL query builder (SQLCase/SQLZoomTarget/SQLTree), Request settings, Tree, Wallet, Timeline range

**Rules:**

- The builder case is chosen from request settings (tree/user/wallet/timeline/zoom-target)
- Zoom-target and clustered variants override the base query per zoom level
- Queries are bounding-box constrained to the tile envelope

**Flows:**

- **Select and Build Tile Query** (`Map controller invocation`): Inspect request settings, choose the matching SQL builder case, assemble the query with variant overrides, and execute it.
- **Build Single-Tree Query** (`Map controller (single-tree request)`): Produce a parameterized SELECT for one tree, resolving numeric id versus UUID and joining related data.

### Style & Projection Config

Generates the Mapnik XML style for each tile and provides the spherical-mercator projection. It injects zoom-aware SQL and the database connection into a PostGIS datasource template, and converts tile coordinates to geographic envelopes.

**Terms:** Mapnik XML template, PostGIS datasource, SQL CDATA parameter, Zoom level, Projection constants

**Rules:**

- Clustered SQL is used at low zoom and per-tree SQL at high zoom
- The SQL is injected into the postgis.xml datasource CDATA table parameter
- Projection constants are precached per zoom level

**Flows:**

- **Generate Mapnik Style XML** (`Map build (per tile)`): Assemble a zoom-aware Mapnik XML style by injecting SQL and the database connection into the PostGIS datasource template.
- **Project Tile Coordinates** (`Map build (per tile)`): Convert tile x/y/z to a geographic bounding box using precached spherical-mercator constants.

### Database Access

Provides pooled, cached access to the PostGIS database. It wraps a PostgreSQL connection pool with an LRU cache and coalesces identical in-flight queries to avoid duplicate concurrent reads.

**Terms:** Connection pool, LRU cache, Query result, In-flight query queue

**Rules:**

- Identical concurrent queries are coalesced into one database read
- Completed results populate the LRU cache for reuse

**Flows:**

- **Serve Pooled Query** (`PGPool.query call`): Serve a query from cache or a coalesced in-flight read, otherwise execute on a pooled connection and cache the result.

### Deployment & Delivery

Builds, packages, and deploys the tile server. A CI pipeline versions and containerizes the app, and Kustomize overlays deploy it to dev, prod, and test namespaces with Ambassador routing.

**Terms:** Docker image, Kustomize overlay, Ambassador Mapping, Kubernetes Service/Deployment, Sealed secret

**Rules:**

- Production deploys are approval-gated
- Each environment layers its overlay on a shared Kustomize base
- External /tiles/ traffic is routed by Ambassador to the service

**Flows:**

- **Build and Publish Image** (`push to default branch`): CI pipeline versions the app, builds the Docker image, and pushes it to the registry.
- **Deploy to Environment** (`workflow_dispatch (deploy-*.yml)`): Manually dispatched workflow applies a Kustomize overlay for the chosen environment and exposes the service via Ambassador.

### Native Rendering Engine

Supporting upstream C++/Node-API Mapnik bindings. It loads the compiled addon and exposes Map, Image, Datasource, and Projection wrappers that rasterize a configured map into an image buffer.

**Terms:** Mapnik Map, Image, Datasource, Projection

**Rules:**

- The compiled addon is loaded at module init and wrapper classes are registered
- Rendering produces a raster image from a loaded map and envelope

**Flows:**

- **Initialize Bindings and Rasterize** (`addon module load`): Load the compiled Mapnik addon, register wrapper classes at init, and rasterize a configured map to an image buffer.
